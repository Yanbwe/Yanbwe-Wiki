# 兼容性问题

## ImmediatelyFast

本模组与ImmediatelyFast一起安装时,会导致本模组在热键栏渲染的物品背景纹理的高透明度部分消失.使游戏在使用默认纹理的情况下,热键栏上的物品背景纹理看上去只有原来的3/4.不过,在GUI内的物品背景渲染不会受到影响.

关闭ImmediatelyFast的HUD批处理功能即可恢复正常.

## EMI

本模组与EMI同时安装时,EMI的"批处理"功能会导致EMI标签页中大量物品不会渲染物品背景.

关闭EMI的"批处理"功能即可恢复正常.

## zeta (1201.9.2-fix后已修复)

本模组与zeta一起安装时,会因为空指针错误导致游戏在加载阶段崩溃.

本问题已在 1201.9.2-fix 修复,将稀有度核心升级到 1201.9.2-fix 以上即可解决.

## 信雅互联和某些fabric模组 (1201.9.2-fix2后尝试修复)

目前已知某些模组与信雅互联安装时,修改了获取物品原版稀有度的API,间接导致稀有度核心崩溃;

本模组已在1201.9.2-fix2版本添加更完善的检测机制,如果API无法使用,则强制禁用原版稀有度转换功能以免崩溃;

目前作者无法复现问题,如果你能找到是哪些模组导致的,请及时反馈给作者.

## FTB Quests / FTB Library（物品边框渲染兼容）

稀有度核心对 FTB 系列模组（FTB Quests 及其依赖 FTB Library）的物品图标渲染进行了兼容适配（1.20.1 版本已支持；1.21.1 自 1211.14.6 起支持）：

- 任务界面中的任务图标、奖励图标、任务地图、应急物品、奖励通知、完成提示（toast）等位置的物品图标均会正常显示稀有度边框
- 物品名称颜色与物品提示（tooltip）中的稀有度信息（等级、星星）在 FTB 界面同样生效
- 边框显示遵循全局"物品边框渲染"开关与逐级样式配置，与在其他界面中的表现一致
- 1.20.1 未提供该联动的独立开关，边框渲染统一跟随全局"物品边框渲染"总开关（`RarityStyle.json` 的 `defaults.border`）
- 未安装 FTB Library 时该兼容自动停用，不影响游戏运行

## 灵动提示框（ColorTooltips）

同时安装灵动提示框（ColorTooltips）时，物品提示框与物品名称的渲染整体交给 ColorTooltips，稀有度核心主动让位：

- 稀有度提示行（等级名 + 星星）不再由稀有度核心插入，改由 ColorTooltips 显示，避免同一行被两条渲染管线叠加
- **物品名称也不再由稀有度核心按稀有度染色**（1.21.1 自 1211.14.9 起），以免覆盖 ColorTooltips 对物品名的着色，以及物品名本身携带的格式代码（如 `§5…§r`）和自定义颜色

所以在这套组合下，物品名不随稀有度变色是预期行为，而不是开关失效：

- 想让物品名按稀有度变色，移除 ColorTooltips 即可（此时由稀有度核心负责名称染色）；也可以只调整 `RarityStyle.json` 的 `itemNameColor`（逐级 / `defaults`，默认 `true`）来控制稀有度核心自身的名称染色
- 稀有度边框、编辑模式、`/raritycore` 命令、KubeJS 与 API 等其余功能不受影响

> 1.20.1 自 1201.14.1 起即为上述行为；1.21.1 在 1211.14.9 之前只跳过了提示行插入、仍会改写物品名颜色，表现为装了灵动提示框时物品名自带的格式代码/颜色被稀有度颜色覆盖。

## 多人游戏版本一致性要求（1.20.1）

**1.20.1 版本自 1201.14.2 起，网络协议版本提升为 `1.2.0`。**

此前的版本在把 NBT 匹配规则同步给客户端时，会把等值条件（`equals`）中的数值与布尔值统一转成文本，导致标量条件在客户端静默失效——表现为**刚进存档时规则正常，退出重进或重启客户端后失效**，进入编辑模式重新读盘后又恢复正常。1201.14.2 起同步包会保留原始类型（并兼容旧格式数据包），该问题已修复。

由于同步包的语义发生变化，**服务端与客户端的稀有度核心都需要 1201.14.2 或更高版本**：

- 客户端版本过低：连接时会被拒绝（协议版本不匹配）
- 服务端版本过低：即使客户端已升级，规则仍会以文本形式下发

> 1.21.1 与 26.x 不受此影响，没有协议版本变更，无需强制双端同时升级。
